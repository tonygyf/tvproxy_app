请基于我目前这个 Android TV Proxy 项目，对“当前网络信息 / 网络测试”模块进行系统性优化。

项目背景：
这是一个运行在 Android TV / 电视盒子上的代理工具。当前 App 可以通过 WRITE_SECURE_SETTINGS 等权限修改 Android 系统的 Global Proxy，从而让电视部分网络请求经过代理。

当前页面大致结构如下：

【当前网络信息】

第一行：
1. 国内测试：当前显示国内出口 IP、运营商等信息
2. 国外测试：当前显示国外出口 IP、运营商等信息
3. CloudFlare ProxyIPv4：显示 Cloudflare 看到的出口 IP
4. 境外测试：Google / X.com 等网站的出口测试

第二行：
国内：
- 字节抖音
- Bilibili
- 腾讯微信
- 阿里淘宝

国外：
- GitHub
- Telegram
- X.com
- YouTube

页面同时显示各网站的延迟。

请不要简单重做 UI，而是重点优化“测试逻辑、数据来源、代理状态判断和测试结果可靠性”。

==============================
一、IP 检测方案
==============================

请将“IP 检测”和“网站连通性测试”分开。

IP 检测的目标是判断：

1. 当前电视真实出口 IP
2. 当前出口国家
3. 中国大陆情况下的省份
4. 城市
5. ISP / 运营商
6. ASN
7. Cloudflare 出口节点 / colo（如果能够获取）

国内 IP 定位优先使用 IPIP 或其他稳定的 IP 地理数据库。

国内测试希望能够尽量精确到：

省：
例如 广东省 / 上海市 / 辽宁省

城市：
例如 广州市 / 上海市 / 沈阳市

运营商：
中国移动 / 中国联通 / 中国电信等

ASN：
例如 AS4837

国外出口测试建议增加 Cloudflare CDN Trace：

https://cloudflare.com/cdn-cgi/trace

解析其中：

ip
loc
colo
http
等字段。

Cloudflare Trace 主要用于判断当前请求实际从哪个出口 IP / 国家 / Cloudflare POP 发出。

注意：
Cloudflare Trace 主要用于国外出口和 CDN 路径判断，不要把它当成中国大陆省市级 IP 数据库。

==============================
二、国内网站测试
==============================

国内网站测试的目标不是获取 IP，而是验证：

“当前电视经过当前网络环境后，国内常用服务是否可以正常访问，以及延迟是多少。”

保留类似：

- 抖音
- Bilibili
- 微信 / 腾讯
- 淘宝

但请避免单纯依赖首页 HTML 是否成功返回。

优先使用稳定、轻量、适合 Android TV 的 HTTP/HTTPS 测试地址。

要求：

1. 请求时间短
2. 返回数据小
3. 尽量稳定
4. 不依赖复杂 JS
5. 不依赖登录
6. 不因为页面缓存导致测试结果错误
7. 能够明确区分：
   - DNS 失败
   - TCP 失败
   - TLS 失败
   - HTTP 错误
   - 超时
   - 成功

==============================
四、最重要：增加 Proxy 前后对比测试
==============================

当前项目存在一个非常重要的问题：

我通过 Android Global Proxy 强制给电视设置代理。

例如：

未开启代理：

电视
↓
中国运营商
↓
175.xxx.xxx.xxx

开启代理：

电视
↓
Global Proxy
↓
代理节点
↓
Cloudflare
↓
176.xxx.xxx.xxx

理论上应该：

Proxy OFF：
IP = A

Proxy ON：
IP = B

并且：

A != B

但是目前出现：

开启 Proxy 后测试结果发生变化。

关闭 Proxy 并还原 Global Proxy 后，
再次测试时结果仍然显示之前代理状态的结果，没有立即恢复。

请重点排查这个问题。

==============================
五、排查测试结果缓存
==============================

首先排除“只是页面显示缓存”。

测试请求不能只读取：

- Flutter 内存缓存
- WebView 页面缓存
- HTTP Cache
- Service Worker
- localStorage
- SharedPreferences
- 上一次测试结果

每次执行“重新测试”时，应当真正发起新的网络请求。

如果使用 WebView / fetch：

请考虑：

- Cache-Control: no-cache
- Cache-Control: no-store
- Pragma: no-cache
- 给请求 URL 增加随机 query 参数，例如：

?t=当前时间戳

例如：

https://cloudflare.com/cdn-cgi/trace?t=1720000000

目的：

确保关闭 Proxy 后的测试不会因为缓存继续显示旧 IP。

==============================
六、排查 HTTP 长连接
==============================

重点检查：

HTTP Keep-Alive
HTTP/2
HTTP/3
QUIC
WebSocket
连接池
DNS 缓存

因为：

第一次测试可能已经建立：

电视
↓
Global Proxy
↓
代理节点
↓
HTTPS Connection

即使之后关闭 Global Proxy，
原来的 HTTP/2 / Keep-Alive 连接仍可能继续存在。

因此：

“关闭 Proxy 后立即重新测试仍显示代理 IP”

不一定意味着 Global Proxy 没有成功关闭。

测试模块应该尽量保证：

每次网络状态发生变化后重新建立网络连接。

必要时：

- 清理 HTTP connection pool
- 关闭旧连接
- 使用新的请求实例
- 禁止复用旧连接
- 重新建立 DNS / TCP / TLS 连接

不要因为缓存或连接复用导致误判。

==============================
七、排查 DNS 缓存
==============================

关闭 Proxy 后还需要考虑：

DNS Cache

例如：

Proxy ON：
DNS → 代理环境

Proxy OFF：
DNS 仍然使用之前缓存

因此测试逻辑应该尽可能区分：

DNS 缓存问题

和

实际出口代理问题。

不要仅根据一个网站的结果判断 Global Proxy 是否已经恢复。

==============================
八、重点检查 Android Global Proxy
==============================

请检查项目当前设置和清除 Global Proxy 的代码。

重点确认：

1. 设置 Proxy 时到底修改了哪些 Android Settings
2. 清除 Proxy 时是否完全恢复
3. 是否只设置了：
   http_proxy

4. 是否还存在：

global_http_proxy_host
global_http_proxy_port
global_http_proxy_exclusion_list
http_proxy

或 Android 当前版本对应的其他代理字段。

需要确认：

设置代理：

Proxy ON
↓
系统 Settings 中确实存在正确 Proxy

关闭代理：

Proxy OFF
↓
系统 Settings 中已经完全清除 Proxy

不要只修改 UI 状态。

==============================
九、Global Proxy ≠ VPN
==============================

请不要把 Android Global HTTP Proxy 当成 VPN。

Global Proxy 只能影响遵循系统代理配置的网络请求。

以下类型可能不遵循系统 HTTP Proxy：

- UDP
- QUIC
- 某些自定义 Socket
- 某些 App 自己实现的网络栈
- 某些 WebView / Chromium 网络行为
- 某些应用明确绕过系统代理

因此网络测试模块需要明确告诉用户：

“网站访问成功”
不等于
“所有电视网络流量都经过代理”。

==============================
十一、增加“关闭代理后恢复测试”
==============================

建议加入自动验证流程：

步骤 1：
Proxy OFF

获取：

IP_A

步骤 2：
Proxy ON

获取：

IP_B

步骤 3：
Proxy OFF

重新创建网络请求

获取：

IP_C

最终判断：

如果：

IP_A != IP_B
并且
IP_C == IP_A

显示：

🟢 Proxy 工作正常

如果：

IP_A != IP_B
但是：

IP_C == IP_B

显示：

🟠 Proxy 已关闭，但当前网络连接可能仍在复用旧连接 / 存在缓存

如果：

IP_A == IP_B

显示：

🔴 当前测试请求没有检测到出口变化

如果：

IP_C 与 IP_A 不同，但国家 / ISP 等发生变化：

显示：

🟡 网络出口发生变化，但无法确认是否由 Proxy 引起
